VISION–LANGUAGE NAVIGATION / RESEARCH NOTE 001

Navigation
Weight Editing.

Can a small change to NaVILA’s weights make it navigate better? A first experiment in action decisions, stopping behavior and the difference between fewer calls and faster success.

By Zhimin WangNovember 6, 2026NaVILA 8B · 8 frames50 fixed unseen episodes
01 / INSIGHTS

Three things we learned.

01

A tiny output edit can change an entire route.

Editing five output-head rows changed success from 24/50 to 27/50: four gains and one loss. Small local decisions compound in closed-loop navigation. The +6 percentage-point estimate remains uncertain: its exploratory 95% interval spans −2 to +16 points.

Inspect the paired evidence →
02

Distance choices explain more than the STOP edit.

Distance-only matched the combined edit at 27 successes and 17 stops within one meter. STOP-only fell to 23 and 14. A better offline STOP decision did not guarantee a better final stopping location.

Understand the intervention →
03

Fewer calls do not establish faster success.

Overall calls fell 12.2%, mainly on episodes that still failed. On the 23 shared successes, calls increased 9.9%; forward commands did not become longer. This pilot does not demonstrate faster successful navigation.

02 / RESULTS

The evidence, from metrics to motion.

We froze the first 50 episodes in the original R2R-CE val_unseen array and evaluated four variants: baseline, combined, STOP-only and distance-only. All 200 rollouts completed with the same evaluator, observation sampler, greedy decoding, seed, action primitives and step budget. This is a fixed pilot across seven scenes.

02.5 / INTERPRETING THE EVIDENCE

A useful intervention.
An unfinished hypothesis.

Distance editing reproduced the success gain. STOP-only editing did not help. The next challenge is to target efficient movement directly—and make better stopping decisions survive the closed loop.

How strong is the evidence?+

Small and exploratory. The fixed first 50 episodes cover seven unseen scenes; they are not a random sample. The success delta is +6 percentage points with a paired 95% bootstrap interval of [−2, +16]. Exact two-sided McNemar p = 0.375. Scene correlation may make episode-level intervals too narrow.

What does “precise stopping” mean?+

An explicit STOP at a geodesic distance of at most 1 m from the goal. The denominator is all 50 episodes. Standard navigation success requires STOP at less than 3 m. A timeout never counts as a precise stop.

What was held fixed?+

The original val_unseen JSON order (IDs 1–50), evaluator, observation sampler, native prompt, greedy decoding, seed 100, 25 cm / 15° primitives and a 500-step limit. Candidates were selected using development states from the training split. The test outcomes did not choose the edit.

What is this experiment not claiming?+

This is an independent adaptation of a weight-editing framework, not a reproduction of the original robotics paper. It does not demonstrate real-robot speedup, statistical certainty on success, or a full-val_unseen improvement. Recorded inference times are descriptive because compute load varied.

03 / METHOD

A contextual edit to the action readout.

The first experiment uses supervised, forward-only ridge fitting. The intervention changes how existing hidden features are read into native action text.

Why these weights?

NaVILA generates language actions: The next action is move forward 75 cm. or I think I should stop because I have finished the instruction. The opening tokens I and The expose a stop/continue decision; 25, 50 and 75 expose a forward-distance decision. We selected their five rows in llm.lm_head.weight because of this output interface. This selection is an engineering hypothesis, not a causal localization of a navigation circuit.

All five rows have width 4,096. The FP16 checkpoint contains 20,474 changed entries out of 20,480 editable positions. Vision features, transformer blocks and the remaining output rows stay fixed. The patch has a 41.6% relative L2 norm within the five rows, so a small fraction of the full model is still a substantial local intervention.

What the targets actually ask for

We retain the original R2R training annotations. An annotated 25 cm or 50 cm action stays short; only an annotated 75 cm action receives a larger target margin. The objective calibrates annotated choices. It does not contain collision-free distance labels, a one-meter stopping objective, or a task-time loss.

The desired correction is the missing margin over the strongest competing candidate, clipped to [0, 8]. We raise the annotated token and lower its competitors with a zero-sum residual. STOP openings receive nine times the weight of each continue opening to balance one STOP class against nine non-STOP classes.

From forward-pass features to a checkpoint

For a hidden state h, a fixed row update changes a token score by ΔwtTh. Its effect therefore depends on the input context. Weighted ridge regression fits the target residuals, with zero-change answer contexts and regularization limiting collateral changes.

Context-dependent output change
z′t = zt + ΔwtTh
One fixed weight patch; a different effect for each hidden state.

We solve a regularized least-squares system and merge the resulting patch into FP16 weights. There is no backpropagation, optimizer, LoRA, or inference-time logit processor. There is supervised parameter fitting; “gradient-free” does not mean “data-free.”

Data, selection and limits

Fitting uses 480 states and development uses 160, balanced across ten action classes, with at most one state per physical trajectory. They cover 47 fitting and 11 development scenes, disjoint from each other and from the seven test scenes. Development is held out from this edit fit; it is still part of the base model’s original training-data source.

Nine prespecified candidates combine ridge fractions {0.001, 0.01, 0.1} and strengths {0.25, 0.5, 1}. Selection checks continued-action accuracy, STOP recall, short-distance decisions, full-vocabulary predictions and changes at ordinary answer positions. The selected fraction is 0.01, with strength 1. STOP-only and distance-only are row subsets of this same patch, with no refitting.

On teacher-forced development states, STOP recognition rises from 3/16 to 5/16 and 50 cm accuracy from 4/16 to 6/16. The other distance accuracies stay fixed; none of 1,424 ordinary answer-token argmax predictions changes. These narrow offline checks motivated closed-loop evaluation, but do not establish general language preservation or navigation improvement.

Our first-run conclusion is a working localized intervention with an uncertain quality gain. A stronger efficiency experiment needs an explicit account of wasted decisions, stopping behavior and the execution pipeline before choosing a weight edit.

A fresh follow-up: prepared and paused

Protocol v3 starts from the original checkpoint with a fresh research-agent context and no prescribed behavioral diagnosis or edit direction. Development uses training data only. A separate evaluator will measure SR, SPL and nDTW on the exact SenseNova val_unseen rand100 subset after the candidate is frozen. Research-agent token usage will be recorded separately from coordination and model inference.

Five task IDs also appeared in the earlier first-50 evaluation. SenseNova's published initial orientations and ground-truth trajectories differ from the local NaVILA copy, so the exact published dataset/GT pair will be used. This set will be withheld from the new editing process; not every task is globally unseen. All results above belong to Experiment 001; this revised study has not started. 04 / REFERENCES

Ideas behind the experiment.

These works motivate the research question. The first experiment above is our own supervised output-head intervention; its results do not reproduce the mechanisms or headline gains of either weight-editing study.

Robotics Weight Editing ↗

Ziyang Gong et al. · 2026 · Research blog

A study of autonomous investigation and weight interventions for a manipulation policy, including prefix repair and an action-position intervention fitted into attention projections. It motivates our investigate–edit–evaluate workflow. Our NaVILA pilot uses neither its RTC repair nor its temporal RoPE construction.

Sparks of Weight-Space Programming ↗

Rikiya Takehi, Jayden Teoh, Alex Zhang & Omar Khattab · November 2, 2026 · Research blog

Explores whether a general-purpose LLM can interpret and write network weights through reasoning, with access to tools and forward feedback varying by experiment. It supplies the broader weight-space programming perspective. Our first run fits annotated decisions with ridge regression; it does not establish zero-shot circuit discovery or direct reasoning-only weight construction.
